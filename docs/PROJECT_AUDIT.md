# CANguard Project Audit

**Date:** 2026-08-03  
**Scope:** Full repository read (library, experiments, notebooks, tests, docs, figures).  
**Constraint:** No code was modified for this audit.  
**Purpose:** Establish a rigorous baseline before multi-detector experiments and paper repositioning.

---

## 1. Executive Summary

CANguard implements **PIRD (Per-ID Behavioral Residual Detection)**: per-ID sliding windows → 14 behavioral features → per-ID z-score residualization → Isolation Forest (normal-only training) → fixed-FPR thresholding.

The codebase is a careful port of research notebooks into a package with tests, YAML experiment configs, HCRL and ROAD loaders, and diagnostic figures. Scientific honesty about **HCRL presence-based shortcuts** and **DoS failure** is already present in README and docs.

**Critical gap relative to the intended paper hypothesis:**

> *Per-ID behavioral residualization improves multiple anomaly detection algorithms under legitimate-ID reuse while remaining lightweight, interpretable, and deployable.*

The repository currently supports **Residual + Isolation Forest** almost exclusively. Representation ablation (raw vs residual) exists only inside notebooks, not as a first-class multi-detector experiment. There is **no manuscript**, **no committed results tables**, and **no multi-algorithm baseline suite**.

## 3. Architecture (Current System)

```
Frames (HCRL CSV | ROAD .log)
        │
        ▼
  Dataset loader → canonical schema
  (timestamp, can_id, dlc, data_0..7, label, is_attack [+ attack_type on ROAD])
        │
        ▼
  FeaturePipeline (per-ID sliding window, default ws=30)
  → 14 BEHAVIORAL_FEATURES_V1
        │
        ▼
  temporal_split  (HCRL: 40% calib / 20% train / 40% test)
  OR ROAD per-capture protocol (see §5.3)
        │
        ▼
  fit_per_id_stats(calib normals) → transform_residuals
  r_f = (x_f − μ_id,f) / (σ_id,f + ε)
  unseen ID → global normal μ/σ
        │
        ▼
  IsolationForestDetector (n_estimators=200, contamination='auto')
  train: normal-only residual vectors
  threshold: (1 − FPR_target) percentile on val normals (default FPR=1%)
        │
        ▼
  Metrics (P/R/F1/FPR/ROC-AUC/PR-AUC) + figures
```

### Design strengths of the architecture

1. **Canonical schema** isolates loaders from features/detectors.
2. **Detector base class** (`BaseAnomalyDetector`) is ready for multi-algorithm extension.
3. **Feature group constants** (`GROUP_IAT`, `GROUP_FLAT_BYTE`, …) support ablations.
4. **Temporal splits only** — no random shuffles of windows (correct for time series).
5. **Normal-only training + FPR-targeted threshold** matches one-class IDS practice.
6. **Presence features excluded** from the main path (`is_new_id` optional and off by default).

## 4. Experiment Pipeline

### 4.1 Entry points

| Entry | What it does | Output |
|-------|--------------|--------|
| `run_pipeline.py` | Full HCRL residual IF + cross-attack + threshold sweep + figures | `results/pipeline_summary.json`, `figures/*.png` |
| `python -m experiments.runners.train_detector --config …` | Config-driven HCRL residual IF | `results/hcrl/baseline/results.json` |
| `python -m experiments.runners.eval_road --config …` | Per-capture ROAD residual IF | `results/road/road_results.json` |
| `python -m experiments.runners.run_ablation --config …` | Feature-group variants | `results/hcrl/ablation/ablation_results.json` |
| `experiments/scripts/make_road_figures.py` | Bar charts from ROAD JSON | `figures/road/*.png` |
| Notebooks | Research exploration (source of truth for numbers in README) | In-notebook outputs |

### 4.2 Standard HCRL protocol (library + runners)

1. Load first `sample_size=60_000` rows per attack CSV.
2. Fit `known_ids` on first 20k normal rows (only used if presence features enabled — currently not).
3. Build per-ID windows (`window_size=30`, label policy `"any"`).
4. Chronological 40/20/40 split on window table.
5. Fit per-ID residual stats on **calib** normals only.
6. Residualize train/test.
7. Fit IF on train normals (hold out last 20% of train normals for threshold).
8. Threshold ≈ 1% FPR on val normals; evaluate full test set.

### 4.3 Feature set (v1, production path)

| Group | Features |
|-------|----------|
| IAT | `iat_mean`, `iat_std`, `iat_median`, `iat_min`, `iat_max` |
| DLC | `dlc_mode`, `dlc_std` |
| Payload (flat) | `byte_mean`, `byte_var`, `byte_max_change`, `byte_nunique`, `byte_entropy` |
| Other | `window_fill`, `time_since_last_seen` |

**Not in library production path** (only in `pird_v2_extensions.ipynb`): bus-level features, per-byte features, multi-scale windows.

### 4.4 Residualization (core scientific transform)

- Fit μ/σ **per CAN ID** on calibration **normals**, requiring ≥ `MIN_WINDOWS_PER_ID = 20` windows.
- Fallback: global normal μ/σ.
- NaN → residual 0.0.
- EPS = 1e-6 against zero variance.
- Implemented in `src/canguard/features/per_id.py` with equivalence tests vs notebook.

### 4.5 Evaluation metrics currently reported

| Metric | Present? |
|--------|----------|
| Precision, Recall, F1, FPR | Yes |
| ROC-AUC, PR-AUC | Yes |
| Confusion counts (tp/fp/fn/tn) | Yes (internal) |
| Threshold / n_train_normals | Yes |
| Runtime | **No** |
| Memory | **No** |
| Model size | **No** |
| Statistical significance (paired tests, CIs, multi-seed) | **No** |

## 5. Datasets

### 5.1 HCRL Car-Hacking

| Property | Value |
|----------|--------|
| Attacks | DoS, Fuzzy, RPM spoof, gear spoof |
| Format | CSV, variable DLC (loader is DLC-aware — good) |
| Labels | Per-row `R` / attack |
| Evaluation | One continuous stream per file → temporal split |
| Known limitation (documented) | **Presence-based**: new-ID / constant-byte rules get F1 > 0.99 |

**Implication for novelty claims:** Near-perfect residual-IF scores on RPM/gear do **not** prove stealth-attack detection. ROAD is the harder, more relevant benchmark for legitimate-AID reuse.

### 5.2 ROAD (Real ORNL Automotive Dynamometer)

| Property | Value |
|----------|--------|
| Format | `.log` + `capture_metadata.json` |
| Labeling | Injection interval × injection_id (incl. fuzzing `XXX`) |
| Structure | Independent captures (no cross-capture temporal continuity) |
| Relevance | Attacks reuse legitimate AIDs → matches paper hypothesis |

Loader quality is high (interval+ID matching, fuzzing semantics, masquerade naming helpers). Tests cover injected-ID, fuzzing, ambient, factory registration.

### 5.3 ROAD evaluation protocol — **doc vs code mismatch**

**Documentation claims** (`road.yaml`, `docs/road_validation.md`, README):

> residuals fitted on **pre-injection** normal frames of each capture.

**Actual code** (`eval_road.py`):

```python
normals = ft[ft["is_attack"] == 0].copy()   # ALL non-attack windows
stats, global_stats = fit_per_id_stats(normals, FEATURES)
res = transform_residuals(ft, stats, global_stats, FEATURES)
calib, train_df, test_df = temporal_split(res, 0.4, 0.2, 0.4)
```

Issues:

1. **Stats use all normals**, including post-injection normals — not strictly pre-injection.
2. **Temporal 40/20/40 on full residualized capture** can place part of the injection in calib/train/test arbitrarily depending on capture layout.
3. `max_frames_per_capture` is accepted but **never applied** to the loaded frame table.
4. `capture_sample.per_type` in config is **never used** (evaluates all non-masquerade attack logs).

This is a **reproducibility / scientific-validity risk** for ROAD claims and must be fixed or re-documented before paper submission.

## 7. Paper-Relevant Results Already Known (from notebooks)

### 7.1 Residual IF on HCRL (60k rows, ws=30, ~1% FPR target)

| Dataset | F1 | Recall | FPR | ROC-AUC | PR-AUC |
|---------|-----|--------|-----|---------|--------|
| DoS | 0.017 | 0.010 | 0.055 | 0.893 | 0.629 |
| Fuzzy | 0.469 | 0.981 | 0.147 | 0.973 | 0.759 |
| RPM | 0.991 | 0.999 | 0.004 | 0.999 | 0.991 |
| gear | 0.945 | 0.998 | 0.032 | 0.999 | 0.996 |

### 7.2 Raw vs residual IF (notebook ablation — **supports residualization hypothesis for IF**)

| Dataset | Raw IF F1 | Residual IF F1 | Raw ROC-AUC | Residual ROC-AUC |
|---------|-----------|----------------|-------------|------------------|
| DoS | 0.000 | 0.017 | 0.825 | 0.893 |
| Fuzzy | 0.162 | 0.469 | 0.868 | 0.973 |
| RPM | 0.000 | 0.991 | (low) | 0.999 |
| gear | 0.000 | 0.945 | (low) | 0.999 |

**Interpretation:** Residualization is necessary for IF on RPM/gear under this protocol; raw features collapse. This is strong preliminary evidence for the **representation** hypothesis — but only for Isolation Forest and only on HCRL.

### 7.3 Failure modes already identified

| Failure | Evidence | Likely cause |
|---------|----------|--------------|
| DoS (HCRL) | Recall ~1%, F1 ~0.02 | Novel-ID flood; per-ID baselines never see the flood ID; residual falls back to global stats that do not isolate DoS well at 1% FPR |
| ROAD fuzzing | Recall ~0.34, F1 ~0.27 | Cross-ID burst; per-ID norms absorb short multi-ID injection |
| Cross-attack transfer | Near-zero off-diagonal recall | Residual space is attack/dataset-specific; IF does not transfer across attack types |
| Fuzzy FPR inflation | FPR ~0.15 at “1% target” | Threshold from train normals poorly calibrates to test distribution |

### 7.4 Supervised upper bound (HGB on residuals)

Notebook: supervised HGB reaches F1 ≈ 1.0 on DoS/RPM/gear (Fuzzy weaker). Useful as **oracle / separability check**, not as an IDS baseline (uses attack labels).

## 9. Weaknesses (Scientific / Methodological)

### 9.1 Positioning vs hypothesis

| Intended | Current |
|----------|---------|
| Residualization as **CAN-specific representation** that helps **many** detectors | Framed as **PIRD = residual + IF** method |
| Multi-algorithm representation study | Only IF in production code |
| Statistical significance | Single seed (`random_state=0`), no CIs |
| Deployability claims (latency, memory) | No runtime/memory instrumentation |
| Legitimate-ID reuse as primary setting | HCRL still primary path; ROAD secondary and protocol-mismatched |

### 9.2 Missing experiments (mapped to research questions)

| Research question | Status |
|-------------------|--------|
| Does residualization actually help? | Notebook-only for IF; not multi-detector |
| Help every anomaly detector? | Not tested |
| Statistically significant? | Not tested |
| Generalize across datasets? | ROAD partial; protocol issues |
| Real-time capable? | Not measured |
| Which features matter? | Partial ablation; `exclude_groups` broken |
| Where/why does it fail? | Qualitatively yes; not quantified (error analysis, ID-level, attack-phase) |
| Failures quantified? | Tables exist for aggregate metrics only |

### 9.3 Evaluation design issues

1. **Label policy `"any"`**: any attack frame in a window marks the whole window as attack → can inflate recall and dilute precision.
2. **Head sampling 60k rows**: may truncate late attacks or over-represent early bus state; not full-file evaluation.
3. **Train segment may contain attacks**: IF filters normals for fitting (good), but residual calib is first 40% of *all* windows — if attacks start early, calib normals may be short / contaminated by attack-adjacent dynamics.
4. **No multi-seed aggregation**: IF is stochastic; one seed is insufficient for a paper.
5. **No paired raw-vs-residual protocol in library**: critical for representation claim.
6. **Cross-attack residualization uses target calib stats on source train** — intentional but subtle; must be carefully explained or it confounds transfer claims.
7. **No latency/throughput study** despite “lightweight/deployable” claims in intended hypothesis.

### 9.4 Manuscript / artifact gap

- No `papers/` manuscript (LaTeX/Markdown).
- Results directories gitignored and empty → paper tables not versioned.
- Figures committed but generation requires local data.
- README still titles system as “PIRD … Isolation Forest” rather than residual representation study.

## 14. Alignment With Repositioned Hypothesis

### Recommended contribution framing (do not claim)

- ~~“We propose Residual + Isolation Forest as a novel detector.”~~

### Recommended contribution framing (do claim, if results support)

1. **CAN-specific representation:** Per-ID behavioral residualization encodes deviations from each AID’s normal cadence/payload under **legitimate ID reuse**.
2. **Detector-agnostic benefit:** Residual features improve (or fail to improve) a suite of one-class detectors under matched protocol.
3. **Failure characterization:** Quantify when residualization fails (novel-ID flood, cross-ID fuzzing, distribution shift) and why.
4. **Deployability:** Latency/memory/model size at automotive-relevant rates.

### Evidence currently supporting residualization

- Notebook raw-vs-residual IF ablation (HCRL).
- ROAD high recall on targeted single-AID attacks (with protocol caveats).

### Evidence currently challenging residualization / PIRD

- DoS failure under novel-ID flooding.
- ROAD fuzzing failure.
- Poor cross-attack transfer.
- HCRL trivial presence baselines still beat behavioral IF on some presence attacks.

The paper should **own these failures** as scientific content, not defects to tune away after the fact.
