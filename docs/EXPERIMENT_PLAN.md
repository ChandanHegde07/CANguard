# CANguard Experiment Plan

**Status:** Planning document (post-audit). Implementation not started.  
**Hypothesis:**

> Per-ID behavioral residualization improves multiple anomaly detection algorithms under legitimate-ID reuse while remaining lightweight, interpretable, and deployable.

**Contribution framing (do claim if supported):**

Behavioral residualization is a **CAN-specific representation** that enables anomaly detection under legitimate arbitration-ID reuse.

**Do not claim:** “Residual + Isolation Forest is novel.”

**Primary scientific question of Exp 1–2:**

> Does residualization **consistently** improve performance across detectors?  
> If yes, the **representation** is the contribution.

Related audit: [`PROJECT_AUDIT.md`](PROJECT_AUDIT.md).

## 0. Shared Protocol (all experiments unless noted)

All detectors and representations must use the **same** protocol so comparisons are causal on the experimental factor only.

### 0.1 Pipeline stages

| Stage | Fixed choices |
|-------|----------------|
| Features | 14 `BEHAVIORAL_FEATURES_V1` (unless ablation/window varies them) |
| Window | Default `ws=30` (Exp 5 varies) |
| Label policy | `"any"` (document; optional sensitivity later) |
| Split (HCRL) | Temporal 40% calib / 20% train / 40% test |
| Residual fit | Per-ID μ/σ on **calib normals only**; global fallback; `MIN_WINDOWS_PER_ID=20`; `EPS=1e-6` |
| Train | **Normal-only** train residuals (or raw normals) |
| Threshold | Percentile on held-out val normals; default `FPR_target=0.01` |
| Score convention | Higher = more anomalous |
| Seeds | Report multi-seed for stochastic models (default seeds `{0,1,2,3,4}`) |

### 0.2 Representation factor

| Name | Feature matrix |
|------|----------------|
| `raw` | Original window features, `fillna(0)` |
| `residual` | `*_res` columns from `transform_residuals` |

**Critical:** Same window table → same split indices → only the transform differs.

### 0.3 Core metrics (every detection experiment)

| Metric | Notes |
|--------|--------|
| Precision, Recall, F1 | Operating point at ~1% FPR target |
| FPR (actual) | Must report; often ≠ target |
| ROC-AUC, PR-AUC | Threshold-free ranking |
| Runtime | Train + score latency |
| Memory | Peak RSS or model footprint where applicable |
| Model size | Serialized bytes or parameter count |

### 0.4 Datasets

|---------|------|
| HCRL (DoS, Fuzzy, RPM, gear) | Presence-heavy; stress-test / failure modes |
| ROAD (targeted AID + fuzzing) | **Primary** legitimate-ID reuse benchmark |

## Experiment 2 — Representation Study (core contribution test)

### Question

**Does residualization consistently improve performance?**

If yes across detectors and (especially) ROAD legitimate-ID attacks → **representation is the contribution**.

### Design (2 × D factorial)

```
Raw Features  →  Isolation Forest
Raw Features  →  LOF
Raw Features  →  One-Class SVM
Raw Features  →  Elliptic Envelope / HBOS / AE / …
Residual Features → Isolation Forest
Residual Features → LOF
Residual Features → One-Class SVM
Residual Features → …
```

### Primary contrast

For each detector \(d\) and dataset/attack \(a\):

\[
\Delta\text{Metric}_{d,a} = \text{Metric}(\text{residual}, d, a) - \text{Metric}(\text{raw}, d, a)
\]

Report \(\Delta\)F1, \(\Delta\)ROC-AUC, \(\Delta\)PR-AUC, and sign consistency.

### Analysis rules

1. **Consistency:** fraction of (detector, attack) pairs with \(\Delta > 0\).
2. **Effect size:** median \(\Delta\) and bootstrap CI (Exp 7).
3. **Exceptions:** where residual **hurts** (likely novel-ID DoS, some fuzzing) — quantify and explain.
4. **No cherry-picking:** same hyperparameter budgets for raw and residual (or retune both under same search budget).

### Deliverables

| Artifact | Contents |
|----------|----------|
| `representation_results.csv` | Full factorial metrics |
| `representation_delta.csv` | Per detector/attack deltas |
| Figures | Paired bar charts; win/loss matrix residual vs raw |

### Repo status

| Piece | Status |
|-------|--------|
| Notebook raw vs residual IF | Exists (HCRL only) |
| Library raw path in runners | **Missing** (runners always residualize) |
| Multi-detector grid | **Missing** |

### Decision rule for paper claim

| Outcome | Claim |
|---------|--------|
| Residual improves most detectors on ROAD targeted-AID + HCRL RPM/gear | Representation is main contribution |
| Residual helps only IF | Contribution is residual+IF pipeline (weaker; do not overclaim) |
| Residual hurts often | Residualization is conditional; lead with failure analysis |

## Experiment 3 — Feature Importance

### Question

Which residual features drive detections? Supports interpretability claim.

### Methods

| Method | Protocol |
|--------|----------|
| **Leave-one-feature-out (LOFO)** | Retrain detector without feature \(j\); \(\Delta\)metric vs full set |
| **Permutation importance** | Permute feature \(j\) on test (or val) only; drop in metric / score quality |
| **SHAP or surrogate SHAP** | TreeSHAP if using IF/ surrogate RF on scores; KernelSHAP only if sample budget allows |

**Surrogate SHAP (recommended if IF importances unavailable):**

1. Fit residual IF; get anomaly scores on a sample.
2. Fit a transparent regressor (e.g. HistGradientBoosting) predicting scores from features.
3. Explain the surrogate with TreeSHAP; validate surrogate \(R^2\) on held-out scores.

### Controlled factors

- Representation: **residual** (primary); optional raw for contrast
- Detector: default Isolation Forest (and one non-tree detector if LOFO differs)
- Dataset: HCRL RPM/gear (success) + DoS (failure) + one ROAD targeted attack

## Experiment 4 — Feature Ablation

### Question

What is each feature’s contribution under matched protocol? Rank by impact.

### Design

For each feature \(f_j\) in the 14-feature set:

1. Train full model (baseline residual + default detector).
2. Remove \(f_j\) only; retrain + re-threshold (same FPR target).
3. Record:

\[
\Delta F1 = F1_{\text{full}} - F1_{-j}, \quad
\Delta ROC = ROC_{\text{full}} - ROC_{-j}, \quad
\Delta PR = PR_{\text{full}} - PR_{-j}
\]

Also run **group ablation** (IAT / DLC / flat_byte / other) — fixes audit B3 (`exclude_groups`).

## Experiment 7 — Statistical Significance

### Question

Are improvements (esp. residual vs raw) statistically meaningful under non-IID CAN windows?

### Methods

| Method | Use |
|--------|-----|
| **Bootstrap CI (95%)** | For F1, ROC-AUC, PR-AUC on test windows |
| **Cluster-aware bootstrap** | Resample by **time block** and/or **CAN ID** and/or **capture** (ROAD) to avoid IID window assumptions |
| **Paired bootstrap** | Residual vs raw on identical test indices |
| Multi-seed mean ± std | For stochastic detectors |

### Avoid

- Treating successive windows as IID for CI.
- Unpaired tests across different test sets.
- Reporting only point estimates from seed 0.

### Deliverables

| Artifact | Contents |
|----------|----------|
| `bootstrap_ci.csv` | metric, estimate, ci_low, ci_high, cluster_unit, n_boot, dataset, detector, representation |
| Paper tables | Point estimate [95% CI] |

### Suggested defaults

- `n_boot = 1000` (or 200 for expensive models)
- Block length: e.g. 1–5 s of windows, or one capture on ROAD
- Report both window-bootstrap (optimistic) and block-bootstrap (conservative)

## Experiment 12 — Cross-Dataset Transfer

### Question

Does a residual model trained on one corpus transfer to another without retraining?

### Protocols

| Direction | Train | Test | Residual stats |
|-----------|-------|------|----------------|
| HCRL → ROAD | HCRL normals (per attack or pooled normals) | ROAD capture | Fit on HCRL calib only; apply to ROAD features |
| ROAD → HCRL | ROAD ambient / pre-injection normals | HCRL test | Fit on ROAD only |

**Feasibility note:** Feature spaces match (same 14 features). ID spaces differ — per-ID residual stats **do not transfer** by ID. Options (document which is used):

1. **Global residual only** at transfer (no per-ID) — fair cross-vehicle stress test.  
2. **Per-ID on source; target IDs use global source stats** — measures representation + detector transfer under domain shift.  
3. **Refit residual stats on target calib, freeze detector** — hybrid; not pure transfer.

Primary paper claim should use (1) or (2); (3) is “detector transfer only.”

### Metrics

Degradation \(\Delta\)F1, \(\Delta\)ROC, \(\Delta\)PR vs in-domain; discuss vehicle/bus/attack mismatch.

|----------|------|
| `transfer.csv` | `tables/transfer.csv`, `experiments/transfer/` |

## Experiment 18 — Scientific Validation of Central Hypothesis

### Hypothesis (test; do not force)

> Residualization improves anomaly detection **regardless of detector**.

### Decision procedure

1. From Exp 2: for each detector, compute paired \(\Delta\) on primary metrics (block-bootstrap CIs from Exp 7).  
2. **Strict true:** residual better (CI excludes 0) on ≥ \(k\%\) of detector×primary-attack cells, no large systematic harm.  
3. **Partially true:** holds for density/tree methods and/or legitimate-ID spoofing; fails for novel-ID flood / cross-ID fuzz.  
4. **False:** residual rarely helps or often hurts under matched protocol.

### Rules

- Do **not** drop detectors that hurt residualization.  
- Do **not** retune residualization after seeing multi-detector results.  
- Pre-register success criteria in this plan; report outcome in `FINAL_REPORT.md`.

### Deliverables

Hypothesis verdict + evidence table + honest Discussion section.

## Scientific Guardrails

1. Do not tune residualization on test to inflate multi-detector wins.  
2. Report **actual FPR** whenever F1 is reported.  
3. HCRL near-perfect scores do not prove legitimate-ID generalization — pair with ROAD.  
4. Presence baselines stay as dataset-limitation checks, not “SOTA IDS.”  
5. **Negative results stay in the paper** (DoS, fuzzing, residual hurts X, transfer collapse).  
6. IID-free statistics for primary claims (Exp 7 block bootstrap).  
7. Same compute budget when comparing detectors.  
8. Never optimize only for benchmark numbers — optimize for **truth**.  
9. If an experiment weakens the paper, **keep it**.  
10. If the hypothesis is disproven or partial, **say so** (Exp 18).
